# Solar Lens HK 2.2 — review, recovery and performance

Released 3 November 2026. Model weights and supplied candidate datasets are unchanged. This release improves the workflow and performance; it does not claim higher detection accuracy.

## New controls

- Select inventory rows or the current page, then mark reviewed, mark needs review, exclude or restore together.
- Undo/Redo retains up to 20 recent review, bulk, drawing, calibration, setting and completed-scan changes. Keyboard shortcuts: Ctrl/Cmd+Z and Ctrl/Cmd+Shift+Z outside inputs and dialogs. History is local to the open study and clears on study/photo replacement or reload.
- Data library can back up all saved studies, previews and reviews in one JSON. Restore validates the complete backup before merging by ID; the newest saved timestamp wins. Original high-resolution photos are not included.
- The current-photo controls show estimated tile workload and working resolution. Last scan details records the actual source, tiles, elapsed seconds, confidence threshold, resolution and timestamp.
- Reversed years or scan resolutions differing by more than 25% withhold change figures. Matching coverage, correct dates and comparable image quality still require human checks.
- The existing v2.1 PowerPoint guide is linked under How it works.

## Fixes and recovery

- Reattaching a matching original to a saved preview preserves counts, notes, outlines, calibration and dates. It skips automatic detection even when automatic scanning is enabled. Explicit rescans remain available and can be undone.
- Storage writes start immediately, coalesce newer edits and retain failed records for retry. The current-project record and saved-study records commit together. The Saved indicator confirms completion; browsers can still interrupt an unfinished transaction.
- Delayed startup/demo loads cannot overwrite work started while they were loading. Native-detail requests check image identity before reading the view.
- Inference workers recover after errors; tensor cleanup also runs when decoding fails. Cancellation is checked between polygon-merge batches.
- Unavailable remote study downloads no longer hide saved local work. A retry button reloads supplied data; missing values remain unknown.
- Imports reject malformed IDs, duplicate IDs, invalid flags/settings, invalid or excessive geometry and invalid previews. JSON cannot supply runtime readers/cleanup functions.

## Performance

The production entry JavaScript decreased from **416.95 kB to 251.03 kB** uncompressed (39.8% smaller), or **133.16 kB to 84.04 kB** gzipped (36.9% smaller), compared with v2.1. Leaflet and GeoTIFF are separate on-demand chunks. This is the entry bundle only: model, WASM, imagery and optional chunks still download when needed.

Unchanged summaries, projected outlines and SVG paths are cached. Number formatters and inference padding canvases are reused; library searches are debounced. Saved preview decoding is reused during scanning. Preview and detail canvases are bounded in both dimensions, including very tall photos; replaced bitmap resources are closed.

Reproduce calculation timings with `npm run benchmark`. One local run on the 22 supplied photos / 2,963 candidate regions measured:

| Calculation workload | Uncached | Cached |
| --- | ---: | ---: |
| Summary, 12 passes | 89.68 ms | 4.42 ms |
| Geographic export, 6 passes | 1,533.32 ms | 251.96 ms |

Each includes a cold first pass followed by unchanged passes. Order, JIT warmup, hardware and system load affect results. These are calculation microbenchmarks, not end-to-end latency or inference-speed measurements.

## Verification

- All **38 automated tests pass**, including the original current-photo identity regression and atomic paired-scan commit checks.
- Production build passes with 194 transformed modules.
- Browser: real inference on the imported `sample-2025.tif` produced 38 regions and 1,893.9 m² at 0.10 m working resolution in one run. A001's manually entered count survived reload and original reattachment; Undo recovered it after an explicit rescan.
- Browser: bulk review/exclusion and undo/redo, measurement-setting updates, whole-library backup download and restore, supplied-study search/filter, current and all-library maps, and reversed-date warning passed without application console errors.
- Responsive checks at 390 × 844 px found no document-level horizontal overflow in Comparison or Data library. Inventory tables retain their own horizontal scrolling.

Counts remain area-based estimates until a physical count is entered. Review labels are workflow status. Supplied registration uncertainty and other measurement limits still apply; see the main README and application methodology.
